- envelope: user_id = 로컬 IPv4, ts = KST, command = JSON 문자열.
  직원 사번이 아니다. assistant.message에는 prompt와 response가 함께 들어간다.
- 전송은 최대 2회, 각 시도 timeout 2초, 재시도 간격 250ms. 별도 로컬 감사 fallback 없음.
- TUI 홈에 개인(신용)정보·민감정보 입력 주의 안내.
- 감사 endpoint는 빌드 상수. 소스 개발 실행에는 이 상수가 없어 감사가 비활성화됨.
  회사 사용/정책 검증은 사내 빌드 실행파일 기준으로 해야 한다.
- 이는 완전한 OS/네트워크 sandbox가 아니다. 사용자 직접 셸(!), 플러그인 자체
  프로세스/통신, 모델 공급자 통신 및 MCP 서버 권한을 일괄 통제한다고 설명하지 않는다.
- allow 목록에는 cp/mv/sed/awk/dd 등도 있다. 모든 변경 작업에 승인을 요구하는 정책은 아니다.

5. 사용자 질문에 답한 내용

rg:
- 두 버전의 Grep은 ripgrep 실행파일에 의존. 시스템/PATH 및 OpenCode cache/bin에서 탐색하고,
  없으면 GitHub에서 15.1.0을 다운로드한다. 다운로드 실패 시 JS/system grep 대체 경로 없음.
- Windows rg.exe와 Mac rg는 다르고 CPU별 파일도 다르다.
- 배포본에는 Windows x64와 macOS ARM64 rg를 각각 동봉했다.

내장 서브에이전트:
- 현재 v1/v2는 실제 호출 및 결과 반환이 검증됐다.

- v2는 실행 중 개수, Subagents 탭, 자식 세션 이동 및 완료 알림이 있다.
- v1 background는 별도 experimental flag가 필요하며 배포 런처가 켠다.

- 예전 사용자의 정확한 증상을 재현한 것은 아니므로 '이전 문제 전부 해결'이라고 단정하지 않았다.

8. 유지보수 및 주의사항

- 사용자 제공 AGENTS.md 및 각 package AGENTS.md를 따른다.
- tests는 packages/opencode 등 package 디렉터리에서 실행. root test 금지.
- typecheck는 package의 bun typecheck. tsc 직접 호출 금지.
- Conventional commit 사용. 기존 두 회사 브랜치에서 연속 작업 가능.
- v2 세션 코어의 durable admission / process-local runner 경계를 유지한다.
- 이 대화에서 Codex sub-agent를 생성하지 않았다. 제품 subagent 질문은
  Codex 작업 위임 요청이 아니며, 사용자/AGENTS 명시 없이는 새 에이전트를 만들지 않는다.
- ZIP/컴파일 바이너리/node_modules/프로필/API 키는 Git에 추가하지 않는다.
- 내부 도메인, 실제 감사 endpoint, 조직 식별 문자열은 토큰이 아니어도 공개 Git에 기록하지 않는다.
- 실제 endpoint가 포함된 build-info.json/패키징 입력/바이너리는 사내 반입용 로컬 파일로만 관리한다.
- 소스와 재현 자료는 Git, 현재 실제 실행파일은 위 바탕화면 폴더에 있다.
- 이 인수인계 저장 이후 진행된 수정 여부는 git log와 새 사용자 지시로 확인한다.
