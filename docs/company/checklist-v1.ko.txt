OpenCode v1 사내 검증 체크리스트
작성일: 2026-10-01 (KST)
대상: 1.18.33-company.2 / Windows x64 및 Apple Silicon Mac

중요: 현재 배포본의 확인된 결함
동일 세션에서 회사 정책상 승인(ask)이 필요한 요청 두 개가 대기할 때,
하나를 '항상 허용'하면 일치하는 다른 대기 요청도 별도 승인 없이 해제되는 경우를
실제 Permission 서비스 재현 테스트에서 확인했습니다.
기대: 두 번째 요청은 승인 대기 유지. 실제: 대기 요청 0개로 감소.
이전 검증에서 놓친 동시 승인 처리 경로입니다. 아래 P6은 현재 실패로 기록합니다.
수정 전에는 '한 번만 허용'을 사용하고 정책 검증 완료로 판정하지 않습니다.
이번 문서는 체크리스트이며 기존 바이너리/ZIP을 수정한 배포본이 아닙니다.

OS/CPU:                     OpenCode 버전:

모델이 도구를 호출하지 않으면 해당 도구 검사는 '미실시'입니다.
AI의 '실행했다/차단했다'라는 설명만으로 판정하지 말고 실제 도구 카드/결과를 확인합니다.

준비 (약 3분)
1. 빈 테스트 폴더를 만들어 이 폴더에서 start.cmd 또는 start.command로 실행합니다.
2. 개인정보나 운영 소스 대신 아래 내용을 가진 qa.txt를 직접 준비합니다.
   QA_SEARCH_20261001
   alpha=1
3. 사내 모델 설정을 배포 폴더의 config/opencode.json에 넣습니다.
4. 감사 로그 담당자가 QA_SEARCH_20261001 등 테스트 표식을 검색할 수 있게 합니다.
5. 정책 검사는 AI에게 셸 도구 실행을 요청합니다. 터미널에 직접 입력하거나
   OpenCode의 ! 직접 셸 기능으로 실행하면 같은 정책 경로를 검사하는 것이 아닙니다.

검증 범위 및 최종 판정
- 핵심: F1~F7 기능, P1~P9 도구 정책, L1~L3 감사 로그를 OS별로 기록합니다.
- P6 결함이 남은 현재 배포본은 회사의 '매번 승인' 정책 전체 통과로 판정하지 않습니다.
- 이 정책은 도구 권한 통제이며 완전한 프로세스/네트워크 격리 기능이 아닙니다.
  사용자 직접 셸(!), 플러그인 자체 프로세스/네트워크, MCP 서버의 실제 권한까지
  이 체크리스트 통과만으로 보장하지 않습니다. MCP는 일괄 차단 정책이 아닙니다.
- 허용 명령 목록에는 cp/mv/sed/awk/dd 등 수정 가능한 명령도 있습니다.
  '삭제 명령 승인 필요'를 '모든 파일 변경 승인 필요'로 해석하지 않습니다.
- '항상 허용'에 따른 순차 요청과 동시 대기 요청의 동작은 별도 점검 대상입니다.
- 자동 업데이트/모델 목록 조회 비활성화는 외부 통신 전체 차단을 의미하지 않습니다.
- oh-my-openagent는 배포 ZIP에 포함되지 않았습니다. 별도 설치 시 버전과 설정을
  기록하고 그 플러그인의 작업 위임/백그라운드 표시를 따로 재시험합니다.
  내장 task 성공을 플러그인 호환성 성공으로 대신하지 않습니다.
