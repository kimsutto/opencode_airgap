# 컴플라이언스 로깅 경계

## 개요

회사가 추가한 내장 플러그인으로, 세션 활동을 로컬에 기록하고 선택한 감사 이벤트를 원격 endpoint로 전송한다.

## 찾아볼 위치

| 관심사 | 위치 | 설명 |
|---|---|---|
| 이벤트 수집·분배 | `plugin.ts` | 플러그인 훅, 중복 방지, 원격 상태 토스트 |
| envelope·전송 | `writer.ts` | 로컬 JSONL, KST 타임스탬프, IP 기반 사용자 ID, HTTP POST |
| 런타임 재정의 | `../../../core/src/v1/config/config.ts` | `compliance.endpoint`가 가장 높은 우선순위를 갖는다 |
| 내장 플러그인 등록 | `../plugin/index.ts` | 기본 플러그인을 비활성화하면 함께 비활성화된다 |
| 빌드 타임 기본값 | `../../script/build.ts` | `OPENCODE_COMPLIANCE_ENDPOINT`를 바이너리에 주입한다 |
| 운영 설명 | `README.md` | `.env` 및 CI 주입 예시 |

## 데이터·전송 계약

- 로컬 로그는 항상 `.opencode/compliance-log/<sessionID>.jsonl`에 파일 모드 `0600`으로 기록한다.
- 공통 envelope `{ user_id, ts, command }`를 유지한다. `command`는 버전이 포함된 이벤트 라인을 직렬화한 값이다.
- Endpoint 우선순위는 런타임 설정, 빌드 타임 상수, 빈 값에 따른 원격 비활성화 순이다.
- 사용자 메시지는 원격 전송 완료를 기다리며, 도구와 권한 이벤트는 백그라운드로 전송한다.
- 원격 실패는 fail-open이다. 채팅과 로컬 기록은 계속되며 TUI 알림은 상태가 바뀔 때만 표시한다.
- 어시스턴트 텍스트와 reasoning은 로컬에만 남긴다. 사용자 내용, 도구 인자·출력, 권한 이벤트는 원격으로 전송될 수 있다.

## 보안·운영 제약

- 로그에는 민감한 평문 데이터가 프로젝트 내부에 저장된다. 테스트나 진단 과정에서 커밋·출력·노출하지 않는다.
- Endpoint 비밀정보를 로그에 남기지 않는다. 현재 빌드는 endpoint를 출력하므로 인증정보가 포함된 URL은 재설계 전까지 안전하지 않다.
- 런타임 endpoint 재정의와 `disableDefaultPlugins`는 원격 감사를 변경하거나 비활성화할 수 있다. 운영 문서에 이 사실을 유지한다.
- 원격 전송에는 현재 timeout, 인증 정책, 재시도, 내구성 큐가 없다. 전송 보장을 주장하지 않는다.
- Endpoint 주입은 바이너리 빌드 경로에 유지한다. 값이 없는 로컬·개발 빌드는 의도적으로 원격 전송을 비활성화한다.

## 검증

현재 전용 자동화 테스트가 없다. 변경 시 이벤트 선택, 로컬 파일 권한, endpoint 우선순위, 원격 실패 동작에 대한 패키지 단위 테스트를 추가하고 `packages/opencode`에서 `bun typecheck`를 실행한다.
